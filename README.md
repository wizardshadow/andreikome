# ANDREIKO — Agency

Публичный сайт и админка `/admin` работают в одном Cloudflare Worker на Sites.

## Редактирование

Войдите через ChatGPT под аккаунтом владельца. В админке доступны тексты, услуги, меню, социальные ссылки, слайды, карточки работ, изображения, видео, метаданные и параметры анимации.

- «Сохранить черновик» сохраняет изменения в серверное R2-хранилище.
- «Предпросмотр» открывает сохранённый черновик, доступный только владельцу.
- «Опубликовать» применяет черновик ко всем посетителям без сборки исходников.
- «История публикаций» восстанавливает версию в черновик; публикация выполняется отдельно.
- JSON-экспорт предназначен для резервного копирования контента.
- `/ANDREIKO-Agency.zip` экспортирует текущую публичную версию сайта с используемыми загруженными медиа.

Посетители не получают черновики и доступ к административным API. Изменяющие запросы проверяют идентификатор и email, переданные платформой Sites, а также Origin. Для аккаунта владельца используется серверный allowlist. При передаче сайта новому владельцу обновите OWNER_EMAIL в `scripts/build.mjs`.

## Исходники

- `public/` — HTML, CSS, клиентский JS и исходные медиа.
- `server/default-content.json` — начальное содержимое; после первой публикации актуальный контент хранится в R2.
- `server/worker.mjs` — авторизация, черновики, публикации, медиа и серверная выдача сайта.
- `scripts/build.mjs` — автономная сборка Worker без внешних зависимостей.
- `.openai/hosting.json` — неизменный project_id и логическое R2-подключение.

Сборка встраивает используемые исходные ресурсы сайта в Worker. Неиспользуемая прежняя подложка `assets/work0.png` не включается. Новые медиа хранятся в R2 и не увеличивают размер Worker. Сгенерированный `dist/` в Git не хранится.

## Локальная проверка

```sh
npm run build
npm test
npm run dev
```

Локальная R2-совместимая файловая база находится в игнорируемой `.cms-local/`.

Для автоматизированной проверки авторизации: `node scripts/dev.mjs --auth`. Только этот локальный адаптер распознаёт cookie `cms-dev-user=owner` и `cms-dev-user=other`; в production Worker такой возможности нет. Сервер слушает исключительно `127.0.0.1`.

Секреты и пользовательские загрузки не коммитятся. Развёртывание выполняется через Sites с текущими настройками доступа сайта.
